## 1. 개편 목적

관리소장이 **지금 개입해야 할 것을 알아채고, 근거를 보고 결정하고, 그 결정이 기록되는** 흐름을 만든다.

관리소장 화면은 기능(FR-301~309)이 전부 동작한다. 그러나 체험해 보면 ① 운영 현황이 "현황판"이 아니라 수치와 목록의 나열이고 ② 상세 화면에 반려·배정·분류 정정이 같은 무게로 널려 있어 무엇을 해야 할지 화면이 말하지 않으며 ③ **완료된 건의 조치 결과와 반려된 건의 사유를 관리소장이 볼 수 없어** "이력 축적 → 정비 근거"(AS-01)라는 핵심 가치가 관리자 쪽에서 끊긴다.

이번 개편의 목표:

1. **개입 시점이 보인다.** 지연·미배정·기사별 현재 작업이 한 화면에서 위계를 갖고 읽힌다.
2. **결정에 근거가 붙는다.** 배정할 때 담당 설비와 여유가, 반려할 때 원문과 같은 위치의 민원이 옆에 있다.
3. **결정이 남고 되돌아볼 수 있다.** 배정·회수·반려 직후 안내가 뜨고, 완료·반려된 건의 결과가 상세에 보인다.

완성도는 화면의 수나 지표의 개수가 아니라, 관리소장이 화면을 오가지 않고 한 건의 개입을 끝낼 수 있는지로 판단한다.

## 2. 범위와 유지할 정책

### 2.1 개편 범위

| 화면 | 경로 | 개편 내용 |
| --- | --- | --- |
| A-01 운영 현황 | `/admin` | 현황판 재구성: 개입 필요(지연) → 기사 현황(현재 작업) → 오늘 흐름. 타일을 필터 링크로 |

W-01 직원 로그인·WORKER·USER 화면은 이미 개편했다. 이 문서는 ADMIN만 다룬다.

### 2.2 유지할 업무 정책 (기술서 기준 — 바꾸지 않는다)

- 선점(Pull) 기본, 관리소장의 배정은 **예외 경로**다. 예외 경로의 전제는 "작업자별 현재 보유 건수·진행 상태가 관리소장 화면에 제공될 것"(기술서 6장). 이 전제가 A-01·A-04의 존재 이유다.
- **P-02** 지연 판정 긴급 1시간 / 보통 6시간 / 낮음 24시간 = 관리소장 개입 시점의 판단 기준. (9.3)
- 배정·재배정·회수·반려의 상태 전이는 9.2 그대로: 배정 `RECEIVED→IN_PROGRESS`, 재배정 `IN_PROGRESS→IN_PROGRESS`(담당만 교체), 회수 `IN_PROGRESS→RECEIVED`, 반려 `RECEIVED|IN_PROGRESS→REJECTED`.
- **관리소장은 분류 정보(위치·설비·긴급도)만 수정한다.** 신고 원문(제목·내용·사진)은 건드리지 않는다. 상태와 무관하게 가능. (FR-307, 10.4)
- **D-01** 중복은 사후 반려 + 원본 연결. 등록 시 자동 탐지는 하지 않는다. 중복 반려에 원본은 필수(`400 ORIGINAL_REQUIRED`). (9.4)
- 작업자 보유 현황은 **보유 건수**로만 표시한다 — 상태 모델에 `ASSIGNED`가 없어 "진행/대기"를 나눌 수 없다. (16.1)
- 동시 보유 상한 없음. 쏠림은 관리소장이 재배정으로 조정. (9.3)
- 평균 처리 시간은 접수(REGISTER) ~ 완료(COMPLETE) 간격으로 산출한다. (14.2)
- **용어는 기술서를 기준으로 화면을 맞춘다.** USER·WORKER 개편에서 확정한 원칙. ADMIN 화면은 ROW의 제안대로 **질문형이 아니라 용어형**으로 간다. (P-B)
- 디자인 규칙: 좌측 네이비 레일 + 전폭 테이블, 헤어라인·면 분할, 8px 사각 인디케이터, radius 3px, 경고색 `#B3401E` 하나, 상태는 채움 방식으로 구분. 카드+그림자·알약 태그·한쪽 색 테두리 금지. **행동은 그 대상이 있는 컨테이너 안에**(제목 블록 우측), 페이지 행동(새로고침·필터)만 헤더.

### 2.3 이번 개편에 포함하지 않는 것

- 직원(기사) 계정 등록·관리 화면 — 결정 P-A. 기본안은 불포함.
- 장소(층·공간)의 엔티티 분리 — 결정 P-F. 기본안은 불포함(2차 범위 기록).
- 실시간 갱신·알림. 수동 새로고침 유지.
- 기사 근무 일정·위치 추적. "지금 사람이 어디 있는지"는 **현재 맡은 작업의 위치**로 대신한다.
- 통계의 내보내기·인쇄, 차트 라이브러리 도입. 막대는 현재의 CSS 막대를 유지한다.
- 모바일 최적화. ADMIN은 데스크톱 전제. 900px 이하에서 깨지지만 않게 한다.
- 발표 자료의 자동 수정. API 명세·ERD·기술서는 7장 채택분만 별도 승인 후 반영한다.

## 4. 디자인 방향

### 4.1 화면의 성격

**운영 현황은 현황판, 전체 민원은 대장, 상세는 결정 화면, 통계는 근거 자료다.**

- 현황판: 지금 개입해야 할 것과 지금 누가 무엇을 하는지를 한눈에. 스크롤 없이 한 화면.
- 대장: 조건을 걸어 찾는다. 조건이 무엇인지 항상 보인다.
- 결정 화면: 상태에 따라 할 수 있는 행동만 보이고, 근거(원문·사진·같은 위치·기사 여유)가 옆에 있다.
- 근거 자료: 기간을 고르고 숫자를 읽고, 숫자를 눌러 대장으로 내려간다.

"AI틱함"을 빼는 기준 — 균등 분할 흰 박스, 상황 무관 안내 문장, 자동 생성 결론 문장, 헤더 우상단 고정 행동, 질문형 라벨, 모든 값이 같은 회색인 부제, 항상 열려 있는 편집 폼은 쓰지 않는다.

### 4.2 공통 시각 기준

직원 콘솔 토큰(`src/styles/main.css`)과 WORKER 개편에서 만든 규칙을 그대로 쓴다.

| 항목 | 기준 |

### 4.3 공통 레이아웃

- 레일 메뉴: `운영 현황` / `전체 민원` / `통계` (P-B).
- 페이지 헤더: 제목 + 사실 서브타이틀(`미배정 11건 · 지연 3건 · 14:20 기준`). 상세·반려는 헤더에 제목만.

## 5. 개편 후 사용자 흐름

### 5.1 개입 (지연 민원 배정)

`운영 현황 → 지연 민원 행의 [배정] 또는 행 클릭(상세) → 배정 모달(담당 설비 일치 기사 먼저) → 지정 → 상세(안내: "{이름} 시설기사에게 배정했습니다")`

### 5.2 정리 (오분류·중복)

`전체 민원(조건 조회) → 상세 → 분류 정보 수정(접힌 섹션) → 저장(안내) / → 반려 → 원문·같은 위치 민원 보며 사유 선택 → 원본 연결 → 반려 → 상세(반려 사유 섹션, 안내)`

### 5.3 재배정·회수

`상세(작업 중) → 재배정(현재 담당 표시, 다른 기사 선택) / 배정 회수(확인 + 메모) → 상세(안내)`

### 5.4 근거

`통계(기간 프리셋) → 설비·층 막대 클릭 → 전체 민원(해당 조건·기간) → 상세(완료 건의 조치 결과)`

## 6. 화면별 상세 기획

### 6.1 A-01 운영 현황 (현황판)

**목적:** 지금 개입해야 할 것과 지금 누가 무엇을 하는지를 스크롤 없이 본다.

```text
운영 현황                                              [새로고침]
미배정 11건 · 작업 중 3건 · 오늘 완료 1건 · 14:20 기준

■ 지연 민원 3건                                 전체 보기 →
 긴급   7층 회의실   냉방 작동 안 함   공조       1시간 18분 전   [배정]
 긴급   지하 1층 기계실   배전반 경고등   전기·조명  2시간 20분 전  [배정]

기사 현황
 김도현  급배수·위생   1건   6층 화장실 세면대 누수 · 맡은 지 20분
 정민수  전 설비       1건   1층 승강기 소음 · 맡은 지 2시간 30분
 박정훈  전기·조명     1건   3층 복도 전등 깜빡임 · 맡은 지 1시간 30분
 이상철  공조          0건   —
 한승우  급배수·위생   0건   —
```

- 수치 타일 4개는 없앤다. 큰 숫자는 **지연 민원 N건** 하나(경고색). 미배정·작업 중·오늘 완료는 서브타이틀의 사실 문장으로 내리고 각각 전체 민원 필터 링크로 연결(AX-08, AX-10).
- 지연 목록: 6건까지, 행 클릭 → 상세, 행 끝 `[배정]` → 배정 모달을 바로 연다(개입 동선 1단계 단축). 경과 열 104px nowrap(AX-09). `전체 보기` → `/admin/complaints?delayed=1`.
- 기사 현황(AX-11): 보유 건수 + **현재 작업(제목·위치·맡은 지)**. 정렬은 활동 중(보유 많은 순) 먼저, 0건은 `—`. 다건이면 가장 오래된 작업을 표시하고 `외 N건`. 행 클릭 → `/admin/complaints?assignee={id}&status=IN_PROGRESS`.
- 지연 목록이 비면 `지연 민원이 없습니다.` 한 줄. 위젯을 채우지 않는다.
- 서브타이틀 "판교 오피스 B동 · 오늘"은 삭제. 기준 시각은 데이터를 읽은 시각.

**API 영향:** `GET /dashboard` 응답의 `workers[]`에 `current: [{id, title, floor, space, assignedAt}]`를 추가한다(P-C). `listComplaints`에 `assignee` 필터를 목에서도 지원한다(명세에는 이미 있음).

### 6.2 A-02 전체 민원 (대장)

**목적:** 조건을 걸어 찾는다. 조건이 무엇인지 항상 보인다.

```text
전체 민원
23건 · 지연만 · 급배수·위생 · 6층 · 9/1~9/16                      [필터 해제]

[제목 또는 민원 번호      ][검색]   상태 [전체][대기][작업 중][완료][반려][취소]   □ 지연만
설비 [전체 ▾]   층 [전체 ▾]   긴급도 [전체][긴급][보통][낮음]   기간 [from] ~ [to]        정렬 [최신 접수순 ▾]

상태      긴급도   위치          요청 내용                          설비        담당 기사   접수
■ 지연    긴급     7층 회의실    냉방 작동 안 함                     공조        —          1시간 18분 전
                                M-260915-C9M4T7
□ 대기    보통     6층 화장실    변기 물 안 내려감                   급배수·위생  —          15분 전
```

- 열 순서: 상태(+지연 마커) → 긴급도 → **위치(굵게)** → 요청 내용(제목 굵게, 번호 부제, 최대 480px) → 설비 → 담당 기사 → 접수 경과(AX-01, AX-02). 관리자는 전 상태를 보므로 상태 열은 유지한다(WORKER와 다름).
- 필터 재편(AX-04, AX-05): 상태는 세그먼트, **지연만은 별도 체크 스위치**(AX-03), 설비·층은 select, 긴급도 세그먼트, 기간 from~to. 기간은 API 확장(P-H) 전까지 표시 계층에서 `createdAt`으로 거른다.
- 활성 조건 요약 줄(AX-03, AX-06): 건수 + 걸린 조건을 사실로 나열, `필터 해제`는 검색어까지 전부 지운다.
- 검색은 버튼과 Enter 둘 다. 필터·검색어·정렬은 URL 쿼리와 동기화(`router.replace`)한다. 대시보드 링크 `?delayed=1`, `?assignee=`, `?status=`, `?category=`가 그대로 초기 조건이 된다.
- 빈 상태(AX-07): `{조건 요약} 조건에 맞는 민원이 없습니다.` + `필터 해제`.
- 정렬: 기본 최신 접수순(API 그대로). `오래된 순` / `긴급한 순`은 표시 계층.
- 행 클릭 → 상세. 상세의 `← 전체 민원`은 쿼리를 보존해 돌아온다.

### 6.3 A-03 민원 상세 (결정 화면) + A-04 배정 + 배정 회수 확인

**목적:** 상태에 따라 할 수 있는 행동만 보이고, 근거가 옆에 있다.

공통 순서 (내용 폭 최대 1100px):

1. 돌아가기 링크 (`← 전체 민원` / `← 운영 현황`, 진입 경로 기준)
2. 상태 인디케이터 + 지연 마커, **민원 제목** — 같은 행 우측에 상태별 행동(AX-14, AX-31)
3. 한 줄 메타: **`6층 화장실`** · 급배수·위생 · 보통 · 35분 전 접수 · 담당 김도현 시설기사(작업 중일 때) · `M-…`(모노 회색) (AX-13)
4. 행동 직후 안내 note (AX-19)
5. 본문 열: (상태별 우선 섹션) → 신고 내용 → 첨부 사진(AX-15) → 같은 위치에서 진행 중인 민원(관리소장에게도 — 중복 판단 근거) → **분류 정보 수정(접힌 보조 섹션)**
6. 보조 열: 처리 이력 → 담당 기사(작업 중일 때: 이름·담당 설비·보유 N건)

**상태별 행동과 본문 우선** (AX-16, AX-17)

| 상태 | 행동 (제목 블록 우측) | 본문 우선 섹션 |
| --- | --- | --- |
| `RECEIVED` | `배정` (주) · `반려` (경고 외곽선) | 신고 내용 |
| `IN_PROGRESS` | `재배정` (주) · `배정 회수` · `반려` | 신고 내용 + 보조 열 담당 기사 |
| `COMPLETED` | 없음 | **조치 결과**(내용·처리 시간·조치 사진·완료 시각) |
| `REJECTED` | 없음 | **반려 사유**(유형·설명·원본 민원 링크와 원본의 현재 상태) |
| `CANCELED` | 없음 | 취소 시각 안내 한 줄 |

**분류 정보 수정** (FR-307 — 모든 상태에서 가능, 그러나 보조)

- 본문 하단 `분류 정보 수정 ▾` 접힌 섹션. 펼치면 층·공간·설비 select + 긴급도 세그먼트 + `저장`.
- 저장 후 note `분류 정보를 수정했습니다 (설비 · 긴급도).` 이력 note는 **한글 라벨**로 기록(`설비, 긴급도`)(AX-18). 변경이 없으면 `바뀐 항목이 없습니다.`
- 설명문("신고 내용 자체는 고치지 않습니다…")은 접힌 섹션 안 한 줄 힌트로.

**A-04 배정 / 재배정 모달** (AX-20)

- 제목: 배정이면 `담당 기사 배정`, 재배정이면 `담당 기사 재배정`. 설명: `담당 기사를 골라 주세요.`
- 표: 이름 · 담당 설비(이 민원의 설비와 일치하면 `●` 표식) · 보유 N건 · 현재 작업(있으면 제목 요약).
- 정렬: **설비 일치 기사 → 보유 적은 순 → 이름순.** 재배정이면 현재 담당 행은 `현재 담당`으로 표시하고 선택 불가.
- 버튼 `닫기` / `배정` (재배정이면 `재배정`). 선택 전에는 비활성 대신 `기사를 골라 주세요.` 힌트.
- 성공 시 모달 닫고 상세 재로딩 + note `{이름} 시설기사에게 배정했습니다.` / `재배정했습니다.`
- 실패(`409 INVALID_STATE`): 모달 안에 `이 민원은 지금 배정할 수 없는 상태입니다.` + 닫으면 재로딩.

**배정 회수 확인** (AX-21, P-D)

- 제목 `배정을 회수할까요?`. 본문: 민원 제목·위치, `현재 담당 {이름} 시설기사`. 메모 `회수 사유 (선택)`.
- 설명: `회수하면 미배정 목록으로 돌아가고, 기사의 내 작업에서 사라집니다.`
- 버튼 `그대로 두기`(초기 초점) / `회수`(경고색). 성공 시 note `배정을 회수했습니다.`

### 6.4 A-05 민원 반려

**목적:** 원문과 같은 위치의 민원을 보면서 사유를 남긴다.

```text
민원 반려                                    ← 민원 상세
■ 대기  6층 화장실 변기 물 안 내려감 · 6층 화장실 · 급배수·위생 · M-260915-B4N9R2

┌ 근거 (좌, 320px) ──────────────┐  ┌ 반려 (우, 720px) ─────────────────────────┐
│ 신고 내용                        │  │ 반려 사유 *   [중복 민원][관리 대상 외][내용 확인 불가] │
│ 6층 화장실 두 번째 칸 …          │  │ 신고자에게 보일 설명 *  [textarea]              │
│ 첨부 사진 없음                   │  │ 원본 민원 *  (중복일 때)                        │
│ 같은 위치에서 진행 중인 민원      │  │   ■ 작업 중  6층 화장실 세면대 누수 · A7K2Q9 · 김도현 [선택] │
│   ■ 작업 중 세면대 누수 (김도현)  │  │   다른 민원 찾기 [제목 또는 번호      ][검색]     │
└──────────────────────────────────┘  │ [반려]  그만두기                               │
                                      └────────────────────────────────────────────┘
```

- 좌측에 원문·사진·같은 위치 진행 중 민원을 병기(AX-22). 후보 목록의 기본값은 **같은 층·공간·설비의 미종료 민원**(WORKER 상세의 `relatedActive`와 같은 조건), 검색은 그 아래 보조(AX-23).
- 라벨은 용어형: `반려 사유`, `신고자에게 보일 설명`, `원본 민원`(AX-26). 안내 박스 삭제, `원본 민원` 라벨 옆에 `신고자는 원본 민원에서 진행 상황을 봅니다.` 한 줄(AX-25).
- 검색 입력·버튼은 한 줄 고정(`.lookup-row`), 버튼 nowrap(AX-24).
- 주 행동 `반려`는 폼 하단, 경고색. 제출 시도 허용: 설명이 비면 `설명을 입력해 주세요.`, 중복인데 원본이 없으면 `원본 민원을 선택해 주세요.`를 항목 아래 표시.
- `그만두기` → 상세로(뒤로가기가 아니라 명시 경로). 입력이 있으면 이탈 확인.
- 성공 시 상세로 이동 + note `반려했습니다. 신고자에게 사유가 보입니다.` 상세에는 반려 사유 섹션(6.3).

### 6.5 A-06 통계 (근거 자료)

**목적:** 기간을 고르고 숫자를 읽고, 눌러서 대장으로 내려간다.

```text
통계
기간  [전체 기간] [이번 달] [최근 3개월]  ·  [from] ~ [to] [적용]         현재: 전체 기간

총 접수 21건 — 완료 5건 · 반려 2건 · 처리 중·대기 14건
평균 처리 시간 2시간 28분 (접수 → 완료)        반려율 9.5%

설비별 발생 건수                              층별 발생 건수            [건수순 | 층 순서]
급배수·위생  ████████████ 8  38.1%             8층  ███ 3
전기·조명    ████████ 5  23.8%                  7층  █ 1
…                                               …  지하 2층
```

- 지표 위계(AX-27): 큰 숫자는 총 접수 하나. 완료·반려·진행은 같은 문장의 숫자. 평균 처리 시간·반려율은 그 아래 보조. 4구역 타일은 없앤다.
- 기간(AX-28, P-I): 프리셋 `전체 기간` / `이번 달` / `최근 3개월` + 사용자 지정. 적용 중인 기간을 우측에 항상 표시. `전체 기간`이 곧 해제다.
- 막대 클릭 → `/admin/complaints?category=WATER&from=…&to=…`(설비) / `?floor=…`(층)(AX-30). 층별은 `건수순 | 층 순서` 토글, 기본은 건수순.
- 자동 결론 문장은 삭제(AX-29). 판단은 관리소장이 한다.
- 데이터 없음: `이 기간에 접수된 민원이 없습니다.` + `전체 기간` 버튼.
- 평균 처리 시간 정의는 P-G 결정에 따른다(기본안: 접수 → 완료).

## 10. 완료 검수 체크리스트

### 10.1 흐름

- [ ] 운영 현황에서 지연 민원이 가장 크게 읽히고, 행의 `배정`으로 모달이 바로 열린다.
- [ ] 기사 현황에 현재 작업(제목·위치·맡은 지)이 보이고, 활동 중 기사가 위에 있다.
- [ ] 서브타이틀의 미배정·작업 중·오늘 완료를 누르면 전체 민원이 그 조건으로 열린다.
- [ ] 전체 민원에서 층·긴급도·기간 조건으로 조회된다 (FR-301).
- [ ] 활성 조건이 요약 줄에 보이고, `필터 해제`가 검색어까지 지운다. 새로고침해도 조건이 유지된다.
- [ ] 지연만 스위치가 상태 세그먼트와 분리돼 있다.
- [ ] 상세에서 상태별로 허용된 행동만 보인다(완료·반려·취소는 행동 없음).
- [ ] 완료 건에 조치 결과·처리 시간·조치 사진이, 반려 건에 사유·원본(현재 상태 포함)이 보인다.
- [ ] 첨부 사진 파일명이 보이고, 없으면 "첨부 사진 없음".
- [ ] 배정 모달에서 설비 일치 기사가 먼저 나오고 표식이 있다. 재배정에서 현재 담당은 선택 불가.
- [ ] 배정·재배정·회수·분류 정정·반려 직후 안내가 뜨고, 다음 행동 시 사라진다.
- [ ] 배정 회수에 확인창이 뜨고, 메모가 이력에 남는다(P-D).
- [ ] 반려 화면 좌측에 원문·같은 위치 민원이 보이고, 같은 위치 민원이 원본 후보로 먼저 뜬다.
- [ ] 통계에서 프리셋·해제가 동작하고 현재 기간이 표시된다. 막대 클릭으로 전체 민원이 열린다.

### 10.2 정책·회귀

- [ ] 상태 전이·지연 판정·API 기본 정렬이 개편 전과 같다.
