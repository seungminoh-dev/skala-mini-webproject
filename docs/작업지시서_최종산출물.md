## 2. 1단계 결과 — 전 FR 플로우 분석 (완료)

### 2.1 방법

Claude in Chrome(사용자 크롬)과 내장 브라우저로 **실제 생애주기**를 액터를 바꿔 가며 실행했다:

`신고자 등록(지하 1층 주차장 · 기타·모름 · 긴급) → 접수증 → 상세 → 수정(비밀번호 오류 → 정정) → 기사 로그인 → 미배정 목록(내 담당 필터·위치 순 정렬) → 상세 → 담당 외 경고 → 맡기 → 내 작업 → 상세(작업 중) → 결과 남기기(선택지 2개 + 메모) → 완료 탭 → 완료 열람 → 신고자 상세(처리 완료·조치 결과·처리 시간) → 관리소장 대시보드(인라인 배정) → 배정 → 재배정 → 회수(사유) → 전체 민원(지연만·필터 해제·URL) → 분류 정보 수정(접힘·저장) → 반려 화면 → 통계(기간) → 별도 민원 취소(2단계 확인) → 기사 반납(사유)`

로그인은 시연 계정 버튼으로 실행(빈 입력 오류, `?redirect=` 복귀, 역할별 진입, 로그인 상태에서 다른 계정으로 전환까지 확인).

### 4.2 시안 1장 먼저

- `techdoc/uiflow/data.cjs`의 W-02 항목을 **새 캡처 기준으로 좌표·내용을 다시 잡아** 1장만 빌드한다:

  - **정보 밀집도** — 주석 4~6개/장, 카드당 1~2문장. 빈 띠가 크면 crop 값 조정.

  - **박스 위치** — 점선/실선/점선 영역이 실제 요소를 정확히 감싸는지, 번호 칩이 겹치지 않는지(원본 캡처 % 좌표는 이미지 뷰어로 측정).
- 시안 승인 전 양산 금지.
